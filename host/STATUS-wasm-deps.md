# wasm-deps — status

**Done. All four libraries built for wasm32-emscripten; smoke test passes under node 20.18.2 and bun.**

- **Versions:** abseil-cpp 20250512.1 (protobuf 36.1's own MODULE.bazel pin) · protobuf **36.1** (C++ runtime 7036001, matches brew host `protoc 36.1` — no fallback to 3.21 needed) · zstd 1.5.7 · wxWidgets 3.2.11 base-only (`wx_baseu`, `wx_baseu_xml`, builtin expat/pcre, port zlib). Prefix `build/wasm-deps/prefix` (33 MB, 98 static libs). Emscripten 6.0.9.
- **Flags, identical everywhere:** `-O2 -fwasm-exceptions -sWASM_LEGACY_EXCEPTIONS=1` + ports `-sUSE_FREETYPE=1 -sUSE_HARFBUZZ=1 -sUSE_ZLIB=1 -sUSE_BOOST_HEADERS=1`, `-DCMAKE_CXX_STANDARD=20`, static, single-threaded, no PIC. All exported by `tools/wasm/env.sh`.
- **`-sWASM_LEGACY_EXCEPTIONS=1` is load-bearing** (three reasons): it is emcc 6.0.9's actual default, so it is what the libs were compiled with; **Node 20 cannot instantiate a module built with the standardised encoding (`=0`) — bun can**; and stating it explicitly dodges an emscripten bug where the freetype port interpolates the default as the Python literal `True` and emcc rejects its own port build.
- **`-DCMAKE_CXX_SCAN_FOR_MODULES=OFF` on the FIRST configure** of every C++20+Ninja project: brew's emscripten has no working `clang-scan-deps`, so module scanning fails every compile *and silently fails every `check_cxx_source_compiles` probe*. Adding it later does not help — bad probe results are already cached (that is how wx concluded `size_t == unsigned int`).
- **`CMAKE_FIND_ROOT_PATH`, not just `CMAKE_PREFIX_PATH`** — the toolchain sets `FIND_ROOT_PATH_MODE_PACKAGE=ONLY`, so protobuf's `find_package(absl)` missed our prefix and quietly FetchContent-downloaded a *second* abseil. Now pinned with `absl_DIR` + `protobuf_LOCAL_DEPENDENCIES_ONLY=ON`, which turns that into a hard error.
- **Patched (1 patch, `tools/wasm/patches/wxWidgets-3.2.11-emscripten-pointer-size.patch`):** wx's `setup.h` took `SIZEOF_VOID_P` from `CMAKE_SIZEOF_VOID_P`, which is left at the host's 8 under emcmake → `types.h`: *"Pointers can't be stored inside integer types."* Now derived from `CMAKE_CXX_SIZEOF_DATA_PTR` (4). Other wx fixes were configure-only: `wxUSE_ZLIB=sys` (bundled zlib calls undeclared `lseek/read/close`), `-DXML_DEV_URANDOM` for bundled expat (no getrandom/arc4random on emscripten), and explicit `wxUSE_PROTOCOL*/URL/FS_INET/DYNAMIC_LOADER=OFF` because `chkconf.h` errors on them once SOCKETS/DYNLIB are off.
- **Finding the KiCad host must act on:** musl starts in the `"C"` locale where `wctomb()` rejects non-ASCII, so `swprintf()` fails and **`wxString::Format()` silently returns an EMPTY string** for any format with non-ASCII arguments. `setlocale(LC_ALL, "C.UTF-8")` before touching wxString fixes it; the smoke test asserts on this.
- **Smoke test** (`tools/wasm/smoke/`, run via `tools/wasm/build-deps.sh smoke`): **81 checks, 0 failures under both node and bun.** Covers wxAppConsole+wxEntryStart+OnInit, wxString/wxFileName/wxFFile/wxFile/wxDir/wxTextFile/wxStandardPaths/wxStringTokenizer/wxDateTime/wxTranslations/wxRegEx/wxFileConfig/wxCmdLineParser/wxXml/wxMemoryInputStream+wxZip+wxZlib, host-protoc-generated protobuf (incl. `GOOGLE_PROTOBUF_VERIFY_VERSION` + descriptors), a throw/catch across the `-fwasm-exceptions` boundary, FreeType face + HarfBuzz shaping from an embedded font, and zstd round-trip. **`smoke.wasm` = 4,756,771 bytes (4.6 MiB).**
- **Wall time ≈ 30 min** (12-core Mac, `-j4`, shared). Re-runs are stamped and skip completed stages. `build-deps.sh` is idempotent: `tools/wasm/build-deps.sh [fetch|abseil|protobuf|zstd|wx|smoke]`.
